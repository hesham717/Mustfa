# إعادة تصميم مشغل الفيديو المدمج — حزمة المواصفات

هذا المجلد هو المرجع الفني لمشغل الفيديو داخل **ES File Manager** (فرع Amaze File Manager،
`com.droidtechlab.filemanager`). الهدف: مشغل من فئة MX Player على أجهزة أندرويد الضعيفة قبل
القوية، بميزانية ذاكرة وطاقة معلنة ومقاسة، لا مضمونة بالكلام.

| اختبارات وحدة للنواة على JVM | **منفَّذة** | 13 صنف اختبار، 128 دالة اختبار (خضراء)، تُشغَّل عبر `:player-core:test` |

## ملخص تنفيذي

**التشخيص.** المشغل السابق كان واجهة واحدة (`VideoPlayerActivity`) تحمل كل شيء: إدارة
الطابور، تفسير الإيماءات، بناء مصادر الوسائط، سياسة الاستئناف، وتنسيق الوقت. ثلاث عواقب
ملموسة: (1) قواعد التفاعل غير قابلة للاختبار إلا يدويًا على جهاز، (2) لا توجد طبقة تمنع
ضبط المشغّل بعيدًا عن قدرة الجهاز، (3) لا توجد قياسات — أي أن عبارة «التشغيل سلس» لا يمكن
إثباتها ولا دحضها.

**الحل المعماري.** فصل المنطق عن المنصة في وحدة `player-core` بلا أي تبعية لأندرويد، وجعل
الواجهة الأندرويدية محوِّلًا (adapter) فقط: تُترجم أحداث ExoPlayer إلى مفردات النواة، وتنفّذ
مخرجاتها. النتيجة أن نفس القواعد (الحالات، الطابور، الإيماءات، سياسة الاستئناف، سياسة فك
التشفير، القياسات) تعمل على أندرويد وiOS وتُختبر مرة واحدة.

**القرارات الثلاثة الأكثر تأثيرًا:**

1. **ميزانية مرتبطة بفئة الجهاز** (`DeviceTier` ← `PlaybackTuning`): حجم التخزين المؤقت، سقف
   الدقة، عدد خيوط فك التشفير، ووضع موسّعات الترميز تُشتق من الذاكرة وعدد الأنوية وإصدار
   النظام، ولا تُترك لقيم ExoPlayer الافتراضية.
2. **محرك إيماءات بلا حالة منصة** (`GestureEngine`): قفل المحور، وعتبة الحركة، ودلتات
   *تراكمية-بين-الأحداث* لا تراكمية-من-البداية — وهذا الأخير أصلح عيبًا حقيقيًا في الكود
   السابق (تطبيق دلتا متراكمة في كل حدث حركة كان يرفع السطوع/الصوت بشكل متسارع).
3. **قياسات QoE من اليوم الأول** (`PlaybackMetrics` + `PlaybackEvent` + `TelemetrySink`):
   زمن أول إطار، نسبة التقطيع، الإطارات الساقطة، كمون القفز، ومعدل البت — بمخطط موحّد
   بين المنصتين.

## كيف تُشغَّل الفحوصات

```bash
# اختبارات نواة المشغل (JVM، لا تحتاج Android SDK)
./gradlew :player-core:test

# ترجمة التطبيق مقابل النواة
./gradlew -PskipGoogleServices :app:assembleFdroidDebug
```

كلا الأمرين مُضمَّنان في `.github/workflows/player-core-ci.yml`، ويُرفع تقرير الاختبار
(`player-core/build/reports/tests`) كقطعة فنية عند كل تشغيل.

## مقياس النجاح المختصر

| الهدف | القيمة |
| --- | --- |
| زمن أول إطار (ملف محلي، جهاز متوسط) | ≤ 200 مللي ثانية (p50) / ≤ 400 (p95) |
| نسبة التقطيع | ≤ 0.5% من زمن الجلسة |
| الإطارات الساقطة | ≤ 0.1% من الإطارات المجدولة عند 30fps |
| ذاكرة المشغل فوق خط الأساس | ≤ 60 ميغابايت (فئة منخفضة) / ≤ 120 (فئة عليا) |
| استهلاك الطاقة | ≤ 350 مللي واط أثناء تشغيل 720p على فئة منخفضة |
| تغطية اختبارات النواة | ≥ 85% من فروع `player-core` |

التعريفات الكاملة وطريقة القياس في [`04-performance-and-metrics.md`](04-performance-and-metrics.md).
